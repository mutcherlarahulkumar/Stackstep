# Transfer the lesson, not just the code

**Estimated effort:** 45 minutes. **Prerequisite:** product explorer, review feedback and audit. This is a lighter consolidation and catch-up day.

## Core work
1. Give a short explorer demo: shareable search, a successful favourite save and a simulated failure with recovery.
2. Explain one design trade-off without notes. For example, why keep confirmed and pending save state separate?
3. Retrieve one earlier idea: reproduce the Two Sum map invariant or explain a stale-response race on paper.
4. Choose one weak test or vague review comment and improve it.
5. Identify one habit to carry into the capstone and one feature you will deliberately avoid to keep scope finishable.

## Done checks
Your evidence links to real code or reproducible steps. The explanation names a cost as well as a benefit. The improved test/comment protects a user outcome. Your capstone preparation acknowledges remaining gaps rather than pretending the earlier projects are flawless.

## If you are behind
Finish a broken core journey or blocking review item first. Do not start capstone scaffolding to escape an unexplained bug. Ask a precise question with the smallest reproduction and the last experiment you tried.

## Hand-in and feedback
Post the demo or written walkthrough, one corrected explanation, and the improved artifact in your task note. Ask a reviewer which claimed improvement has the weakest evidence and strengthen that evidence.

**Optional stretch:** give a teammate a focused review using the same standard. Stop at the timebox and leave space for recovery.
