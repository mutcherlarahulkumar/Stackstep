# A learning log with evidence, not a success story

**Estimated effort:** 45 minutes. **Prerequisite:** at least one PR and one debugging attempt. The historical task title says “week one”; this is an early draft you will revisit on the review day.

## Core work
Write 300–500 words in a Markdown file in your own repository. External blogging platforms are optional, not required.

Use four sections:
1. **Shipped:** one concrete change and a PR link.
2. **Surprised me:** one result that contradicted your prediction.
3. **Debugging:** expected behaviour, actual behaviour, the experiment you ran and what it ruled out.
4. **Next experiment:** one small question you can answer through code next week.

```text
I expected ... because ...
I observed ... in this exact situation ...
I changed only ... and the result was ...
That suggests ..., but I have not yet checked ...
```

## Done checks
A reader can inspect the linked artifact. The debugging section contains an actual observation rather than “I fixed bugs.” Your next step is small enough to test, such as checking keyboard focus on all controls, not “learn everything about CSS.”

## Improve the draft
Remove claims you cannot support. Explain a technical term once instead of stacking jargon. If you used an assistant, state what you verified yourself and what remains uncertain; a generated explanation is not proof of understanding.

## Hand-in and feedback
Submit the repository file or PR link. Ask the reviewer which paragraph is least clear and revise it using their feedback. On day 5, compare the draft with what you learned after the first review.

**Optional stretch:** add one annotated before/after image. Respect other people's privacy and avoid screenshots containing tokens or personal data.
