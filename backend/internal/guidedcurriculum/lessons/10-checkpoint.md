# Check your React reasoning, not your memory of slogans

**Estimated effort:** 20 minutes. **Prerequisite:** components, controlled inputs and filter state.

## Core work
Answer the in-app checkpoint from small mental traces. Before submitting, write your reasoning for the hardest question. After a wrong answer, create a tiny example that tests the idea rather than guessing another option.

Think about these questions:
- Which data is a source, and which value can be derived from it?
- What does a key tell React when a list changes order?
- Does an update depend on a value from a previous render?
- Can an old request still finish after a new one starts?
- What work must be undone when an effect is replaced or a component unmounts?

```text
Prediction -> smallest experiment -> observation -> corrected explanation
```

## Done checks
Complete the quiz with an explanation of one corrected misconception in your task notes. A high score without being able to explain a scenario is a signal to practise, not proof of mastery. The best score counts across the limited attempts; answer keys appear after completion.

## Hand-in and feedback
Submit the quiz in the app and ask the reviewer to change one condition in a scenario. Explain whether your answer still holds. You will revisit stale responses when implementing async loading and URL search.

**Optional stretch:** compare a direct count update with a functional update in a minimal component. Keep the experiment separate from the production UI.
