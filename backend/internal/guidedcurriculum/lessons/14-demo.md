# Demonstrate progress and consolidate the model

**Estimated effort:** 45 minutes. **Prerequisite:** portfolio, tests and review feedback. This is a lighter demo/catch-up day.

## Core work
1. Prepare a three-minute demo: intended user, working journey, one failure state and one known limitation.
2. Link the code and test command so someone can inspect the evidence.
3. Without notes, explain derived state and why old async responses can be dangerous. Check and correct the explanation afterward.
4. Close a review item or explicitly schedule its next step.
5. Choose one improvement to transfer into the next project.

## Done checks
The demo shows real behaviour rather than mock screenshots. You distinguish working features from planned integrations. A limitation is stated honestly. Your next improvement is connected to observed feedback, such as preserving filters on retry.

## If you are behind
Demonstrate the reliable core and explain the missing piece. Prioritize one important review fix instead of starting several unfinished features. A recoverable small product is stronger evidence than a large broken one.

## Hand-in and feedback
Post the demo link or a written walkthrough with screenshots, the corrected explanation and the chosen next improvement. Ask a reviewer to name the least convincing claim and improve its evidence.

**Optional stretch:** review a teammate's demo using one question about the user journey. Leave room for rest before the next project.
